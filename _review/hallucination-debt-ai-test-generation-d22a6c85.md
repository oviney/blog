The AI tools writing your test suites did not learn software engineering. They learned the internet — a particular, ageing snapshot of it, filtered, compressed, and now partly dissolved. That distinction carries consequences, because the web they trained on is vanishing faster than anyone anticipated, and the test suites they produce carry the epistemological weight of a library whose shelves are quietly catching fire. According to Pew Research Center's 2024 analysis, 25% of all webpages that existed at any point between 2013 and 2023 are now inaccessible. A quarter of the web-based knowledge those models gorged on during pretraining — the tutorials, the documentation, the package registries, the annotated stack traces — has ceased to exist at its original address. Engineers who trust AI-generated tests are trusting a model that learned, in substantial part, from things that are no longer there to verify. That is not an edge case. It is the foundational defect of the entire enterprise.

## A Library Eating Its Own Citations

Link rot is not an abstraction. Pew Research Center's 2024 analysis found that 54% of Wikipedia pages contain at least one broken reference link, and 11% of all Wikipedia reference links now resolve to nothing. The encyclopaedia that code-generating models treat as a quality signal for factual grounding has already surrendered a tenth of its cited evidence base to entropy. The situation deteriorates further in journalism: 23% of news webpages carry at least one broken link; 21% of government webpages do the same. Eighteen per cent of tweets vanish within three months of posting. This creates a temporal trap for any model trained on web crawls. The content that survives — older pages, more-replicated entries, widely-mirrored documentation — is by definition more archaic. Research published on arXiv (2502.13347, 2025) found that over 90% of raw web crawl data is discarded before LLM pretraining due to low quality, yet the surviving 10% still carries the temporal biases of its original crawl, skewing toward older, more-replicated content. A model trained on this residue cannot distinguish a package that existed in 2021 from one that exists today. It cannot flag an API whose endpoint has moved, a version whose security advisory has superseded the example it memorised. It produces confident output from partial evidence, because its training rewarded confidence and the evidence has since dissolved into a 404.

## Phantom Packages, Baked-In Biases

Package hallucination is the most measurable symptom. A 2024 arXiv study (arXiv:2406.10279) spanning 576,000 code samples generated by 16 LLMs found that 19.7% of all software package names recommended were hallucinated — non-existent names that no engineer could install. Open-source models fared worse, reaching 21.7%. Even GPT-4 Turbo, the strongest closed-source model tested in that study, hallucinated 3.59% of packages. Those numbers are not confined to a controlled benchmark; they describe the routine experience of developers who ask a code-generating assistant to scaffold a test and receive imports referencing libraries that were deprecated, renamed, or never real. More damning is the structural finding: 43% of hallucinated package names repeated identically across all ten independent runs of the same prompt, according to the same arXiv paper. The errors are not random statistical noise. They are biases baked into the training corpus — almost certainly reflecting stale or absent entries in the data ingested during pretraining. A developer who runs the generated test, watches it fail at the import line, and manually resolves the dependency has paid a tax that appears nowhere on any productivity dashboard. Multiply that correction across every team, every sprint, every CI pipeline running test generation at scale, and the phrase "hallucination debt" stops sounding metaphorical. It becomes a line item nobody has yet budgeted for, accruing silently beneath a layer of green status badges.

## Speed Without Correctness

QA consequences are already visible in aggregate. DevIQA's 2026 State of AI-Generated Code report, which surveyed 300 QA professionals, found that 52% report bug volume has increased since AI adoption — even as developers simultaneously report higher output, with 98% more pull requests merged per developer according to LinearB's analysis of 8.1 million PRs. The productivity gain and the quality degradation are two faces of the same acceleration. AI is generating more code than human reviewers can adequately interrogate, and the tests it appends are not catching what the code is introducing. LinearB's data adds a further layer: AI-authored pull requests are accepted at a rate of 32.7%, against 84.4% for human-authored PRs, and they wait 4.6 times longer for review pickup. Reviewers, whether consciously or not, are applying extra scepticism to AI output. The irony is that AI-generated tests rarely attract equivalent scrutiny. They run, they return a green result, and passing tests are culturally read as evidence of correctness regardless of what they actually assert. A test that verifies the output of a hallucinated dependency, or mocks an API endpoint whose contract shifted after the model's training cutoff, provides the appearance of a safety net while offering none of its substance. It checks that the code does what the model believed it should do — which is an entirely different question from whether the code does what the system requires.

## Security as the Bill Coming Due

Veracode's GenAI Security Report 2025, spanning more than 100 LLMs across 80 coding tasks, found that 45% of AI-generated code samples contained at least one security vulnerability — and the rate held flat across successive model generations. Scaling the model did not reduce vulnerability density. That flatness is the significant signal: if larger, more capable models cannot reduce the rate, the problem is not model capacity. It is the underlying data. Training corpora built from a decade of Stack Overflow answers, forum posts, and tutorials — content now partly inaccessible and therefore unauditable — contain insecure patterns whose subsequent patches the model never witnessed. GitClear's analysis of 623 million changed lines between 2023 and 2026, cited by DevIQA, found that copy-pasted code blocks rose 81% over that period, while refactored code fell from 21% to 3.8% of all changed lines. That is the structural signature of AI-assisted development at scale: suggestions arrive in bulk, get accepted as written, and accumulate without being interrogated. Tests written to cover those blocks without challenging their provenance are not safety nets — they are theatre. A quarter of the web those blocks were drawn from has already dissolved, and the fraction is still rising. Teams that discover this gap will not do so through a failing build. They will discover it through a breach whose root traces to a dependency the model recommended with serene confidence, that was never real, and that every green pipeline run chose, without question, to believe.
